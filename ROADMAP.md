# Agent Roadmap — путь к серьёзному инструменту

Текущее состояние: рабочий прототип с MCP, LTM, RAG и Linear-интеграцией.
Цель: инструмент, который можно использовать в daily work наравне с Claude Code.

Приоритеты расставлены по принципу: сначала то, что даёт максимальный прирост в реальной работе.

---

## P0 — Без этого инструмент не конкурентоспособен

### 1. Поддержка Claude и GPT-4
Сейчас только DeepSeek и LM Studio. Для серьёзной работы нужны топовые модели.

- Добавить `ClaudeProvider` (Anthropic SDK, `claude-opus-4-5`, `claude-sonnet-4-5`)
- Добавить `OpenAIProvider` (GPT-4o, o1)
- Добавить `GeminiProvider` (Gemini 2.0 Flash — дешёвый и быстрый)
- Унифицировать интерфейс: streaming, tool_use, context window per model
- `agent init` — выбор провайдера/модели интерактивно

### 2. Просмотр diff перед применением изменений
Сейчас агент пишет файлы без preview. Это блокирует доверие к инструменту.

- Показывать unified diff перед каждым `write_file` / `move_file`
- Кнопки: `[A]pply / [E]dit / [S]kip / [A]ll`
- Опция `--no-confirm` для CI/скриптов

### 3. Поддержка изображений и скриншотов
Cursor и Claude Code умеют работать с UI. Без этого агент слеп.

- Принимать изображения в сообщении (paste из буфера, путь к файлу)
- Передавать в модели с vision (Claude, GPT-4o, Gemini)
- Применение: разбор скриншотов ошибок, UI-задачи, диаграммы

## P1 — Значительно улучшает daily use

### 4. Веб-поиск и fetch
Агент не может проверить документацию или найти решение в интернете.

- MCP-сервер `web`: `web__search(query)`, `web__fetch(url)`
- Интеграция с Brave Search API или SearXNG (self-hosted)
- Автоматически использовать при вопросах про незнакомые библиотеки

### 5. Запуск тестов и интерпретация результатов
Без этого агент не может верифицировать свои изменения.

- MCP-сервер `test`: запуск `npm test`, `pytest`, `cargo test` и т.д.
- Парсинг вывода: какие тесты упали, где
- Агент автоматически запускает тесты после изменений кода и фиксит падения

### 6. Умная работа с контекстом (context strategy)
Сейчас контекст обрезается тупо по токенам. Нужна стратегия.

- Приоритизация: недавно изменённые файлы → файлы упомянутые в задаче → остальное
- `git diff HEAD` всегда в контексте при работе с кодом
- Автоматический `reindex` при изменении файлов (file watcher)

### 7. Сессии и задачи между агентами
Сейчас каждая сессия изолирована. Нет возможности продолжить сложную задачу.

- Именованные задачи: `agent --task "implement auth"`
- Сохранение прогресса: что сделано, что осталось, какие файлы изменены
- Возможность передать задачу другому инстансу агента

## P2 — Делает инструмент уникальным

### 8. Multi-agent (параллельное выполнение)
Одна из ключевых фич Claude Code — несколько агентов параллельно.

- Оркестратор запускает суб-агентов для независимых подзадач
- Суб-агенты работают в изолированных worktree (`git worktree`)
- Оркестратор мёрджит результаты, разрешает конфликты
- Применение: написать тесты пока другой агент пишет реализацию

### 9. Кастомные workflow и команды
Возможность задать повторяемые процессы под конкретный проект.

- `.agent/workflows/` — yaml-файлы с последовательностью шагов
- Пример: `agent run code-review` → checkout PR → прочитать diff → оставить комментарии
- Пример: `agent run release` → тесты → changelog → bump version → tag

### 10. GitHub/GitLab интеграция
Работа с PR, issues, code review прямо из агента.

- MCP-сервер `github`: `create_pr`, `list_prs`, `comment_on_pr`, `list_issues`
- Агент может сам создать PR с описанием после завершения задачи
- Code review: агент читает diff PR и оставляет замечания

### 11. Улучшенная LTM — обучение на проекте
Сейчас LTM хранит факты, но не учится на паттернах.

- Запоминать: какие инструменты используются в проекте, стиль кода, частые ошибки
- Feedback loop: если агент сделал неправильно и пользователь поправил → запомнить
- Per-project knowledge base, не только глобальная

## P3 — Nice to have

### 12. TUI улучшения
- Syntax highlighting в выводе кода
- Side-by-side diff view
- Индикатор стоимости запроса ($) в bottom bar

### 13. Плагины / хуки
- `pre-tool` / `post-tool` хуки в `.agent/config.json`
- Пример: после каждого `git_commit` → запустить линтер

### 14. Экспорт сессии
- Сохранить сессию как Markdown с историей изменений
- Применение: документирование того что было сделано и почему

## Приоритетный порядок реализации

```
P0: Claude/GPT-4 → diff preview → images
P1: web fetch → test runner → context strategy
P2: multi-agent → GitHub MCP → workflows
P3: TUI → plugins → export
```

даёт доступ к лучшим моделям и разблокирует image support одновременно.
