## Сценарий (запись)

### Шаг 1 — Показать базу знаний

Открыть `demo/kb/` в файловом менеджере. Показать структуру:

```
demo/kb/
  pingvintech/   → 5 файлов (leadership, office, tech, hr, culture)
  osminogssoft/  → 5 файлов
  medveddata/    → 5 файлов
```

> "Три выдуманные компании, 15 файлов. У каждой — одинаковая структура:
> руководство, офис, технологии, персонал, культура.
> Это создаёт шум: поиск по 'зарплата' найдёт всех троих."

---

### Шаг 2 — Показать контраст на одном вопросе

```bash
npm run demo:rag         -- "Кто является CEO компании ОсьминогСофт?"
npm run demo:rag-rerank  -- "Кто является CEO компании ОсьминогСофт?"
```

Обратить внимание:

| | RAG (без фильтра) | RAG + rerank |
|-|-------------------|--------------|
| Чанки в контексте | из всех 3 компаний | только ОсьминогСофт |
| Ответ LLM | неточный или смешивает имена | Геннадий Щупальцев |
| Строка фильтра | нет | `До фильтра: 10 → После: 2` |

> "Без фильтра модель видит CEO от всех трёх компаний.
> С порогом 0.3 выживают только чанки ОсьминогСофт — ответ точный."

---

### Шаг 3 — Запустить полный бенчмарк

```bash
npm run demo:benchmark
```

Скрипт:
1. Автоматически индексирует все 15 файлов через Ollama
2. Прогоняет 10 вопросов по 3 компаниям
3. Для каждого вопроса — сначала RAG, затем RAG+rerank со стримингом

---

### Шаг 4 — Комментировать по ходу

Ключевые моменты для каждого вопроса:

| Вопрос | RAG шум | RAG+rerank победитель |
|--------|---------|-----------------------|
| CEO ОсьминогСофт | 3 CEO-раздела | Геннадий Щупальцев |
| Офис МедведДата | 3 office-раздела | Берлога №42, Тайга-Сити |
| Зарплата МедведДата | 3 hr-раздела | мёд и малиновое варенье |
| Гимн ОсьминогСофт | 3 culture-раздела | «Восемь рук — одна душа» |

> "Смотрите на строку 'до фильтра / после' — видно сколько шума отсеклось.
> Это и есть реранкинг: порог similarity убирает нерелевантные компании из контекста."

---

## Итог (озвучить)

- **RAG без фильтра**: top-K чанков из ВСЕХ компаний попадают в контекст → LLM путается
- **RAG + rerank**: отсечение по minScore=0.3 оставляет только нужную компанию → точный ответ
- **minScore** — простейший реранкер: дёшево, детерминировано, наглядно
- Следующий шаг — cross-encoder или LLM-based reranking для ещё лучшей точности
