# Сценарий демонстрации — День 31: Ассистент разработчика

Живая демонстрация в терминале. Всё делается в настоящей сессии `agent`.

---

## Подготовка (до записи)

```bash
# 1. Убедиться что Ollama запущена
ollama serve

# 2. Сбросить индекс — чтобы индексация сработала на камеру
npm run clean:data

# 3. Перейти в папку проекта
cd ~/Documents/cli-agent
```

---

## Сессия (запись)

### Запуск агента

```
agent --provider deepseek
```

---

### Шаг 1 — Агент знает в какой ветке мы работаем

Напечатать:
```
какая сейчас git-ветка?
```

Агент вызовет `git__git_is_repo` и ответит названием текущей ветки.

> "Агент подключён к репозиторию через MCP. Он знает ветку, может посмотреть diff и статус — без единой shell-команды вручную."

---

### Шаг 2 — Показать список команд

Напечатать:
```
/help
```

Агент выведет статичный список команд.

> "Стандартный /help — просто список. Но у нас есть улучшение."

---

### Шаг 3 — Проиндексировать документацию

Напечатать:
```
проиндексируй документацию проекта
```

Агент вызовет `search__index_documents` с глобом `docs/**/*.md` и `README.md`.
Будет видно как он индексирует файлы и сколько чанков получилось.

> "Агент сам знает что надо проиндексировать — это прописано в системном промпте.
> Ollama считает эмбеддинги локально, результат сохраняется в SQLite."

---

### Шаг 4 — Вопросы о проекте через /help

Напечатать по очереди:

```
/help как добавить новый MCP сервер?
```

```
/help где хранятся API ключи?
```

```
/help какие slash-команды доступны?
```

Для каждого вопроса агент вызовет `search__search`, найдёт релевантные чанки и ответит строго по документации.

> "Это и есть ассистент разработчика: вопрос на русском — ответ из документации.
> Не галлюцинация, а конкретный текст из docs/. Видно даже из какого файла."

---

### Шаг 5 — Обычный вопрос без /help

Напечатать:
```
объясни как работает sandbox boundary в этом проекте
```

Агент сам решит использовать `search__search` и ответит по `docs/architecture.md`.

> "Не только /help — любой вопрос о проекте агент может ответить через RAG.
> /help просто явно направляет его искать в документации."

---

## Итог (озвучить)

- **MCP git** — агент знает ветку, историю, diff прямо в диалоге
- **RAG** — docs/ + README.md проиндексированы локально, поиск за миллисекунды
- **`/help <вопрос>`** — вопрос → поиск по чанкам → ответ строго по документации
- Вся обработка локальная: Ollama для эмбеддингов, SQLite для хранения
